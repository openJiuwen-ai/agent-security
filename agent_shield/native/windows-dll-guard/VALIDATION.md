## 公共 SDK 决策缓存与性能基线（2026-11-13）

公共 `RuntimePermissionEngine` 为单路径读取和裸域名、网络端点分别保存最多 512 条 LRU 规则结果。文件键保留路径大小写，网络键保留完整资源字符串和端口。每次调用仍检查启用状态；文件访问继续执行不可变目录检查。成功更新配置后启用新缓存，配置校验失败则继续使用原策略。缓存只保存策略求值结果，命中 ASK 仍返回 ASK。写入、执行、复合文件操作和完整 URL 各自走原检查流程。

在 Windows x64、CPython 3.13 上，用同一解释器和 DLL 分别测量改动前后。每组预热一轮，再取五轮中位数。前两项测量连续调用同一 SDK 引擎 10,000 次的总耗时。后三项从发起进程启动计时到子进程退出，包含注入和 IPC。引擎在计时前初始化，每轮交替执行普通与受保护进程。

| 负载 | 普通进程，前 / 后（ms） | SDK 或受保护进程，前 / 后（ms） |
|---|---:|---:|
| SDK 重复检查同一路径的读取权限 | — | 16.17 / 8.28 |
| SDK 重复检查同一 IPv4 端点 | — | 226.76 / 12.38 |
| Python 导入 json、asyncio、ssl、decimal、sqlite3 | 237.18 / 247.44 | 496.58 / 482.67 |
| 打开并读取同一文件 500 次 | 73.59 / 69.93 | 518.88 / 506.46 |
| 同一 TCP 连接向回环地址发送 500 次，每次 1 字节 | 87.04 / 92.29 | 347.65 / 340.54 |

以上数据记录仅启用 SDK 规则缓存时的表现，每次原生操作仍经过 IPC。

### 受保护进程内的允许缓存

在同一台 Windows x64 机器上，用同一 CPython 3.13、同一重建 DLL 和同一份显式允许策略，对照动态引擎回调（逐次 IPC）与直接传入引擎实例（启用进程缓存）。两组均保留 SDK 的 512 条规则缓存。每轮交替执行两个模式，各预热一轮后取五轮中位数。从启动子进程计时至退出，包含注入和缓存协商。IPC 次数只统计表中目标文件或端点的决策请求。

| 实际操作 | 逐次 IPC 耗时 / 请求数 | 启用进程缓存耗时 / 请求数 |
|---|---:|---:|
| 对同一文件打开并读取 500 次，每次校验内容 | 461.33 ms / 500 | 137.92 ms / 1 |
| 建立一个回环 TCP 连接并发送 500 次，每次 1 字节，接收端校验完整内容 | 281.84 ms / 501 | 175.22 ms / 1 |

五轮请求数一致。文件策略在同一子进程存活期间从允许改为拒绝的回归中，更新后的首次读取重新进入 IPC 并返回拒绝；配置含差异化读取规则时，每次读取都请求策略检查。

## 验证内容

- 真实进程：注入就绪、进程树归属、文件及网络操作、子程序启动、前后台生命周期和取消清理。
- 审批：在原进程中继续执行，会话与通道隔离、超时及过期回答拒绝、授权范围和保存回调。
- 策略：可信 EXE/argv/cwd、显式拒绝优先、命令批准不能跳过文件与删除检查、策略热更新及更新失败后的旧策略保留。
- Python：脚本启动后的文件策略拒绝与不可变目录执行拒绝分别验证，虚拟环境验证实际解释器、路径和 `init` 参数。
- 分发：SDK 与原生 wheel 的版本、许可、包内默认配置、DLL/源码哈希和已安装产物的真实批准及拒绝执行。
- 兼容：现有 SDK 回归、普通与企业客户端契约、宿主授权和生命周期契约、原生包装协议预检，以及 Linux 上原有功能与纯策略模块。

## 验收边界

文件拒绝用例必须证明脚本已经启动，核对目标文件的拒绝规则、专用退出码及最终内容；不能以任意启动失败代替文件防护成功。不可变目录用例分别验证目录内拒绝和目录外成功，并核对规则与脚本身份。虚拟环境用例独立于不可变目录配置。

自动化回归不代替目标宿主完整应用验收。接入方还需验证全部真实进程创建点经过启动器、审批界面与连接恢复、会话关闭和生产策略组合。受系统应用控制策略限制的注入行为需在目标环境验收。

安全及平台限制见 [功能说明](README.md)。该功能不提供内核强隔离保证。
