# Agent Security

Agent Security 是 openJiuwen 面向 Agent 场景的安全能力仓库。

Agent 和普通程序最大的不同，是它会把模型输出直接变成真实动作：执行 shell 命令、读写文件、访问网络、启动子进程。一次被注入的指令，或者一次模型判断失误，就可能变成删除文件、外发密钥、修改系统配置。只在某一个点上加检查并不够：需要在动作发生前做裁决，在执行时做隔离，在运行过程中做检测，还要把凭据和出站文本管住。

这个仓库把五类能力放在同一棵代码树里，各自安装、各自运行：

- **Agent SSAS** 看运行过程；
- **JiuwenBox** 管执行环境；
- **agent-shield** 判单次动作；
- **Security Gateway** 存敏感凭据；
- **Security Mask** 脱敏出站文本。

几个缩写先说明：SSAS 是 Security Situation Awareness System 的缩写；OCSF 是 Open Cybersecurity Schema Framework，一种通用的安全事件字段标准，便于把告警接入 SIEM；Rail 是 agent-core 中挂在 Agent 生命周期上的拦截钩子。

## 1. 组件一览

| 组件 | 目录 | 解决什么问题 | 交付形态 |
| --- | --- | --- | --- |
| Agent SSAS | `agent_ssas/` | Agent 运行过程不可见，出了问题难以追溯 | Python 包，可进程内嵌，也可起独立 HTTP 服务 |
| JiuwenBox | `jiuwenbox/` | Agent 的命令直接跑在宿主机上，越权读写和删除难以控制 | 独立服务，提供 REST、CLI 与 MCP |
| agent-shield | `agent_shield/` | 每次工具调用缺少统一的 allow / ask / deny 裁决 | 进程内 SDK，另带 Windows 原生防护二进制 |
| Security Gateway | `security_gateway/` | API Key、令牌等敏感字段明文落盘 | Python 库，提供加密字段存储与密钥轮换 |
| Security Mask | `foundation/` | 流式输出里夹带密钥、手机号等敏感片段 | Python 库，按正则做流式星号替换 |

```text
agent-security/
├── agent_ssas/        态势感知：事件采集、威胁检测、OCSF 日志
├── jiuwenbox/         沙箱服务：Linux / Windows 隔离执行
├── agent_shield/      进程内判定：策略引擎、工具权限、原生防护
├── security_gateway/  加密字段存储：schema、密钥、轮换
├── foundation/        流式脱敏工具 security-mask
└── docs/              本目录
```

## 2. 一次工具调用里，它们分别站在哪

假设用户对 Agent 说：“整理一下这个仓库，然后推送。” Agent 决定调用 shell 工具。接下来可能发生这些事：

1. **agent-shield 先裁决。** 它把工具名和参数规范成事件，按内置规则、三方规则、用户规则和已授权 grant 做匹配。比如 `git push --force` 会命中强制推送规则，返回 `ask`；`rm -rf ~` 会命中工作区外强制删除规则，同样返回 `ask`。真正返回 `deny` 的是写入受保护文件、裸盘写入等 critical 行为。
2. **宿主处理 ask。** 如果结果是 `ask`，宿主弹出审批窗口；用户批准后这一次调用放行，拒绝则改成 `deny`。
3. **Security Gateway 提供凭据。** 如果命令需要访问外部服务，密钥先从加密字段存储里取出；落盘的是密文，密钥由分片派生并支持轮换。
4. **JiuwenBox 执行。** 真正跑命令时，命令进入沙箱：Linux 上用 bubblewrap 加命名空间、Landlock、seccomp；Windows 上用受限令牌、Job Object、WFP 和 NTFS ACL。能读哪些目录、能连哪些地址、能不能删除，都由策略决定。
5. **Agent SSAS 记录和检测。** `invoke_start`、`llm_input`、`tool_input` 等生命周期事件被采集进检测引擎，产出风险评估和 OCSF 威胁日志。默认策略是 `observe_only`，只记录不阻断；即使切到 `active_protection`，检测链路自身失败也不会拦住主流程，这是有意的 fail-open。
6. **Security Mask 处理出站文本。** 如果结果要进入网页聊天窗口，命中正则的片段会在流式输出时被替换成星号，避免密钥或个人信息直接显示。

这六步不是强绑定关系。可以只用 agent-shield 做判定，也可以只用 JiuwenBox 做隔离；需要几层就装几层。

## 3. 各组件详解

### 3.1 Agent SSAS：看清 Agent 做了什么

Agent SSAS 是一个安全态势感知系统。它从 Agent 运行时采集事件，送进可插拔的检测模块，最后把结果写成 OCSF 格式的威胁日志，并存进 SQLite。

- **采集什么**：6 类生命周期事件（`invoke_start`、`llm_input`、`tool_input`、`tool_output`、`llm_output`、`invoke_end`）和 1 类安全衍生事件（`permission_interrupt_tool`，其他安全 Rail 的拦截结果）。
- **怎么检测**：检测模块用 `module.yaml` 声明订阅哪些事件、用哪些数据建模插件和威胁分析插件。内置 `agent_moss`、`security_rail_detection`，`test_detection` 默认关闭。
- **怎么运行**：`inprocess` 模式把检测跑在当前进程里，没有网络开销；`http` 模式起一个 FastAPI 服务（默认 `0.0.0.0:8443`），多个 Agent 共用一台分析引擎。
- **怎么决策**：默认 `observe_only`，只记录、全部放行；`active_protection` 在 critical 时阻断，high / medium / low 告警，safe 放行。
- **失败怎么办**：初始化失败、事件格式错误、检测超时都不会拦住调用方，也就是 fail-open。这个选择只针对检测链路自身的故障；一旦检测正常产出 critical 结论，`active_protection` 仍会阻断。这样既不让安全观测成为业务可用性的单点，又保留真正的阻断能力。

**适用场景**：需要审计 Agent 行为、做威胁检测、留下可追溯日志，但不想改动 Agent 主流程。

### 3.2 JiuwenBox：把命令关进沙箱

JiuwenBox 是一个沙箱服务。调用方通过 REST、CLI 或 MCP 创建沙箱、传文件、跑命令，服务按策略文件决定隔离细节。

- **Linux 上**：用 bubblewrap 启动沙箱进程，可叠加网络命名空间、Landlock、seccomp、cgroup、命名空间和 capability 限制。
- **Windows 上**：用受限令牌两跳启动进程，Job Object 限制内存、CPU 和进程数，WFP 控制出站，回环代理过滤域名、IP 和端口，NTFS ACL 控制读写。
- **策略怎么生效**：服务启动时加载根策略；创建沙箱时可以覆盖或追加。`read_only` / `read_write`、`bind_mounts`、`network`、`windows` 等字段决定最终权限。
- **删除怎么处理**：Windows 上设置 `JIUWENBOX_SOFT_DELETE=1` 后，删除先进回收站；失败时转到同卷归档目录，不直接永久删除。
- **失败怎么办**：环境不满足、必需 ACL 缺失、Landlock 在 `hard_requirement` 下不可用，都会让创建或启动失败，不会悄悄降级。

**适用场景**：Agent 需要执行不可信命令、处理外部文件、访问网络，但希望把这些动作限制在可控范围内。

### 3.3 agent-shield：在执行前给出一个决定

agent-shield 是进程内的安全判定 SDK，不调用大模型，也不访问网络。它做三件事：

- **动作决策**：`tool_permission/` 对一次工具调用给出确定性的 allow / ask / deny，内部覆盖命令、路径、出站地址、宿主和删除防护。
- **行为策略**：`policy_engine/` 是策略决策点，支持四层规则、十级优先级、`Decide` 结算和回环 HTTP 服务。三方规则通过规则集接口注册，用户规则和 grant 由宿主传入。
- **内容检测**：`detection/` 对进入模型或工具结果的内容做提示词注入等检测，输出概率性软信号；是否拦截由调用方决定。

Windows 上还有两套原生防护，把文件、进程和网络访问拦在执行前：

- **进程守卫**：`wrap()` 启动独立 `process_guard.exe`，通过 JSON 管道询问裁决，支持回收站删除和 x86 WOW64 子进程。
- **DLL 防护**：宿主进程内的 `RuntimeGuardManager` 注入 `jiuwen_runtime_guard.dll`，通过二进制帧通信，支持运行中审批、授权复用和前后台进程树。

**适用场景**：需要在工具调用或系统调用发生前做统一裁决，并希望结果可解释、可审计、可接入人工审批。

### 3.4 Security Gateway：把敏感字段加密存起来

Security Gateway 是一个加密字段存储库。它按 id 存取记录，字段是否加密由 schema 决定。

- **schema**：宿主在代码里声明记录有哪些字段、每个字段是什么类型、是否加密。
- **密钥**：数据加密密钥（DEK）负责加密字段，DEK 再由密钥加密密钥（KEK）包裹。KEK 由文件、SQLite 和内置常量三份分片异或后再经 PBKDF2 派生。
- **落盘**：记录字段编码成 `VREC` 容器，存进 SQLite 的 `vault_record.data`；schema、密钥元数据和同步状态放在另外三张表。
- **轮换**：支持手动轮换、自动轮换和接管未完成的轮换。
- **边界**：它不监听端口，也不是完整的凭据路由服务；HTTP 接口、凭据路由和 LLM 网关集成由调用方实现。

**适用场景**：需要在本地保存 API Key、令牌、私钥等敏感字段，并且希望有明确的加密边界和轮换机制。

### 3.5 Security Mask：流式输出里的敏感片段替换

Security Mask 是一个很小的流式脱敏工具。调用方传入正则列表，工具边接收字符流边替换命中片段。

- 命中段 11 个字符及以上时保留前 3 个字符和后 4 个字符；5–10 个字符时缩小首尾展示长度，至少藏住 4 个字符；4 个字符及以下时整段替换。中间固定为四个全角星号 `＊＊＊＊`。
- 流式处理时，每次 `push` 会把最后一个分隔符及其之前的内容送去替换，剩下的尾巴继续挂起；没有后续输入时由 `finish` 收尾。分隔符是 `A-Za-z0-9._-+/=@%` 之外的任意字符，因此跨 chunk 的密钥不会被提前截断。
- 规则和开关由调用方持有，它不判断什么是敏感数据。

**适用场景**：网页聊天、日志回显等逐段渲染的输出通道，需要在文本到达用户前做最后一层脱敏。

## 4. 怎么选

| 你的需求 | 先用哪个 |
| --- | --- |
| 想知道 Agent 运行过程中发生了什么 | Agent SSAS |
| 想让危险命令在隔离环境里执行 | JiuwenBox |
| 想在工具调用前得到 allow / ask / deny | agent-shield |
| 想加密保存 API Key、令牌等字段 | Security Gateway |
| 想在网页通道里脱敏流式输出 | Security Mask |

这些组件可以组合使用。一个常见的组合是：agent-shield 负责裁决，JiuwenBox 负责执行，Agent SSAS 负责记录和检测，Security Gateway 负责凭据，Security Mask 负责出站脱敏。
