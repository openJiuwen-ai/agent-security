# Agent Security

Agent Security is openJiuwen's repository of security capabilities. Behavior detection, isolated execution, and in-process decisions are three components in one tree. Each is installed and run on its own.

---

## 1. Components

| Component | Directory | Role |
| --- | --- | --- |
| Agent SSAS | `agent_ssas/` | Collects agent runtime events, runs threat detection, and writes OCSF logs |
| JiuwenBox | `jiuwenbox/` | Sandbox service. Manages sandbox lifetime and isolates commands and file access by policy |
| agent-shield | `agent_shield/` | In-process SDK. Returns allow / ask / deny for a tool call, and checks content before it reaches a model |

```text
agent-security/
├── agent_ssas/     situational awareness
├── jiuwenbox/      sandbox service
├── agent_shield/   in-process decisions
└── docs/           this directory
```

## 2. What each one covers

Agent SSAS watches a run. Lifecycle events go into the detection engine, which produces a risk assessment and a threat log. If detection fails, the caller continues. That behavior is fail-open.

JiuwenBox owns the execution environment. Callers create a sandbox, transfer files, and run commands over HTTP. A policy file decides the isolation. On Linux the service applies that policy with bubblewrap.

agent-shield owns a single decision. Action checks do not use the network and do not call a model. Content detection returns a risk signal. The caller decides whether to stop.

The three components are not one process. The Agent SSAS tutorials live in `agent_ssas/docs/`. Sandbox install and API notes live in `jiuwenbox/README.md`.
